# 과학 포털과 센서 실험실의 국내 접속 속도 개선 계획

**2026-11-04 · 포털·센서 실험실 운영 전환 완료.** 두 사이트 모두 Vercel에서 제공한다.

### 데스크톱 비교 결과

커밋 `7d833bb`을 [Vercel 시험 사이트](https://scope-science-portal.vercel.app)에 배포했다. 같은 Edge에서 매번 새 브라우저 컨텍스트로 두 주소를 번갈아 열고 ‘회로’를 검색해 회로봄 상세 페이지에 도달하기까지 측정했다. 3회 중앙값은 기존 포털 **5.30초(LAX)**, Vercel **1.24초(ICN)**였다. 상세 페이지의 실행 링크도 일치했다.

운영 프로젝트 scope-portal은 GitHub main의 같은 커밋으로 배포했다. 운영 주소에서 같은 동작을 3회 반복한 결과 모두 ICN으로 응답했고 중앙값은 0.60초였다. 센서 실험실도 아래와 같이 별도로 비교했다.

센서 실험실도 [Vercel 시험 주소](https://scope-sensor-lab.vercel.app/)에서 비교했다. 같은 Edge에서 첫 페이지를 열고 입장해 실험실 홈이 표시되기까지 기존 주소는 8.16·6.02·6.96초(LAX), 시험 주소는 2.15·0.46·0.46초(ICN)였다. 시험 브랜치 `test/vercel-region-20261104`에서 `/lab`의 404를 수정했다. 저장 목록 링크의 307 이동과 쿼리 보존, 온도 센서 QR의 공식 주소, 설치 준비 중 받은 HEX 파일의 운영본 일치를 확인했다. 이 규칙을 main에 반영하고 Worker의 운영 도메인 선언을 제거했다. 커밋 d9994b1의 Vercel 자동 배포 후 실제 lab.sco.pe.kr에서 HTTPS 200(ICN), 실험실 입장, 예시 실험 가져오기와 저장 목록에서 다시 열기, QR, 온도 센서 펌웨어 다운로드를 확인했다. USB·Bluetooth 실기기 연결은 별도 확인 대상이다.

## 포털부터 비교하는 이유

11월 4일 같은 한국 회선에서 새 HTTPS 연결로 다섯 번씩 측정했다. 첫 응답 시간의 중앙값은 포털과 센서 실험실이 각각 1.16초(LAX), Vercel의 공개 Astro 데모가 0.32초(ICN), 기존 GitHub Pages 전기회로 앱이 0.27초(ICN)였다. 데모와 포털은 내용이 다르므로, 판단 기준은 **우리 데스크톱에서 같은 포털을 열었을 때 도구를 더 빨리 찾고 실행할 수 있는지**다.

두 사이트의 이전은 완료했다. 배포 변경 주관, 현재 구성과 복구 절차는 [포털 배포 운영 기준](deployment.md)에 기록한다.

## 전송량은 가볍게 관리한다

Vercel을 사용하기 시작하면 몇 차례 사용한 뒤 데스크톱에서 팀의 Usage 화면을 열어 `Fast Data Transfer`를 한 번 확인한다. 이후에는 큰 수업 행사가 있거나 기본 사용량 알림이 왔을 때 추이를 살펴보면 된다. 두 사이트를 같은 팀에 두면 팀 합계를 본다. [Vercel 사용량 안내](https://vercel.com/docs/pricing/manage-and-optimize-usage)

무료 한도에 가까워지면 어느 사이트나 파일의 전송량이 늘었는지 먼저 본다. 필요할 때 해당 사이트의 최신 빌드를 Cloudflare에서 확인하고 운영 주소를 수동으로 되돌린다. 정적 사이트를 두 호스팅에 배포해 DNS로 복구한 운영 사례도 있다. **95GB 감지와 자동 전환·복귀는 한도에 자주 근접해 수동 대응이 부담될 때 다시 검토한다.** [수동 전환 사례](https://brianli.com/2020/12/hosting-on-cloudflare-workers-sites-and-vercel/)
