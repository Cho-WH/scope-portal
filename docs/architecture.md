# 모듈 구조와 설계 결정

## 목적

도구가 늘어날 때 개별 HTML을 복사하지 않고, 콘텐츠를 등록하면 공통 화면이 재사용되는 과학 포털을 만든다. 포털은 도구를 소개하고 연결하며, 개별 실험 앱의 코드나 저장 데이터를 흡수하지 않는다.

## 기술 선택

- **Astro 정적 출력**: 도구·자료를 빌드 시 검증하고 소개 페이지를 생성한다. 검색에 필요한 스크립트를 제외한 페이지 본문은 HTML로 제공한다. [공식 콘텐츠 컬렉션 안내](https://docs.astro.build/en/guides/content-collections/)
- **TypeScript + 스키마**: 필드 오타, 분류 ID 오류, 누락된 자료 연결을 콘텐츠 경계에서 찾는다.
- **프레임워크 없는 브라우저 모듈**: 검색과 탭만 독립 모듈로 동작한다. 전역 앱 상태나 React 런타임을 추가하지 않는다.
- 패키지 버전은 고정하고 `package-lock.json`으로 설치를 재현한다. Node 24는 콘텐츠 검사·단위 테스트의 TypeScript 직접 실행에 사용한다.

## 데이터 흐름

```text
content/tools/*.json + content/resources/*.json
          ↓ schema / validation
       loadCatalog()
          ↓
  페이지 조합 → 공통 컴포넌트 → 정적 HTML
                              ↓
                 검색·필터 / 대표 배너만 점진적 활성화
```

| 경계 | 책임 | 의존하지 않는 것 |
| --- | --- | --- |
| 콘텐츠 | 이름·설명·준비물·실행 주소·자료 연결 | HTML·CSS·브라우저 상태 |
| `lib/catalog` | 데이터 형식·참조·검색 규칙 | 컴포넌트와 DOM |
| 공통 컴포넌트 | 카드·자료·기본 레이아웃 | 특정 도구 ID별 분기 |
| 기능 모듈 | 검색과 대표 배너의 상호작용 | 개별 실험 앱 구현 |
| 페이지 | 기능과 콘텐츠 조합, 안정적인 경로 | 도구별 중복 화면 |

도구의 파일명은 공개 ID이며 `/tools/{id}/` 경로에 사용된다. 저장소나 실행 주소가 달라져도 ID는 유지한다. 자료의 `toolIds`는 다대다 연결을 허용한다. 초안은 공개 목록·경로에 포함하지 않는다.

## 미리보기 경계

현재 `preview.kind`는 `placeholder` 하나뿐이다. `PreviewPlaceholder.astro`는 정적 소개 이미지만 제공한다. 배너의 오른쪽에 현상을 크게 배치하고 글자 쪽으로 페이드한다. 파동은 실제 현상 화면을, 회로·기체는 투명 배경의 정적 SVG 개념 그림을 사용한다. 앱 메뉴·조작부와 눈에 보이는 준비 중 안내는 제외하며 정적 이미지 설명은 보조 기술에 제공한다. 계산, 슬라이더, 애니메이션, 외부 앱 임베드는 구현하지 않았다.

배너 포스터는 `<template>` 안에 두고, 680px 이상에서 선택된 배너에만 삽입한다. 모바일로 전환하면 제거한다. 모바일 최초 진입에는 배너 포스터 요청도 없다. 목록의 대표 이미지(`thumbnail`)는 별도 콘텐츠이며 모바일에서도 제공한다.

실제 미리보기를 추가할 때에는 미리보기 타입과 해당 렌더러를 확장한다. 목록·상세 페이지는 기존 도구 모델과 링크를 계속 사용한다. 도구마다 미리보기 구현을 의무화하지 않는다.

## 화면 설계

- 색상 시안: 어두운 테마를 기본으로 사용한다. 흑연색 바탕 `#25272F`, 본문 `#E7E9EF`, 보조 글자 `#ACB1BF`, 보조 면 `#30333D`, 구분선 `#434855`, 보랏빛 연청색 강조 `#B2BAF5`, 강조 버튼 위 글자 `#222747`. 밝은 이미지와의 명도 차이를 줄이기 위해 배경과 보조 면을 한 단계 밝게 조정했다. 기존 밝은 색 토큰은 보존하되 운영체제의 밝은 모드 설정을 자동으로 따르지 않는다.
- 글꼴: IBM Plex Sans KR. 배너 제목 34px, 섹션 23px, 도구명 18px, 본문 14–15px를 기본으로 한다.
- 배치: `[공통 헤더] → [낮은 소개 배너 + 하단 작은 선택 글씨·이동 밑줄] → [검색·분류] → [3열 큰 이미지형] → [2열 오른쪽 이미지형] → [연결된 수업 자료]`.
- 시안의 과학 그림과 여백, 대표 도구의 이미지 위계를 유지한다. 배너의 중복 도구 이름·활동 분류는 생략하고 질문과 짧은 설명을 사용한다.
- 모바일 배너는 소개와 실행 링크만 제공한다. 미리보기 공간을 남겨 두지 않는다.

### 두 카드 모듈

`FeaturedToolCard.astro`는 목록 순서의 첫 3개에 사용하는 큰 이미지형, `CompactToolCard.astro`는 이후 도구에 사용하는 오른쪽 이미지형이다. 두 모듈은 `ToolCard.astro`의 마크업·접근성·검색 메타데이터를 공유하고, `ToolImage.astro`가 이미지 또는 플레이스홀더를 제공한다. 도구별 분기나 복제 페이지는 없다.

데스크톱 목록은 6칸 그리드에서 큰 이미지형이 2칸, 오른쪽 이미지형이 3칸을 차지한다. 검색·필터 적용 중에는 모두 오른쪽 이미지형으로 표시하여 빈 칸을 만들지 않고, 초기화하면 원래 구성을 복원한다. 모바일에서는 두 모듈 모두 한 줄에 하나씩, 오른쪽에 작은 이미지를 둔다.

`thumbnail`은 배너의 `preview`와 독립적이다. 이미지가 없으면 아이콘과 ‘이미지 준비 중’ 자리만 표시한다. 장치 미연결 화면에 측정값을 합성하지 않는다. 이미지 출처와 캡처 상태는 `docs/tool-images.md`에 기록한다.

목록 이미지는 `ToolImage`의 `background` 표현을 사용한다. 원본 파일을 수정하지 않고 `object-fit: cover`로 영역을 채운다. 큰 이미지형은 아래쪽을 투명하게 하여 설명으로 연결하고, 오른쪽 이미지형은 카드의 오른쪽 배경으로 넓혀 글자와 만나는 왼쪽 경계만 마스크 그라데이션으로 흐린다. 위·아래·오른쪽 경계에는 페이드를 넣지 않는다. 글자와 버튼은 이미지 위의 독립 레이어에 둔다. 모바일에서는 두 유형 모두 오른쪽 배경 방식으로 줄인다. 플레이스홀더에는 투명도와 마스크를 적용하지 않는다.

이미지 전체의 불투명도는 큰 이미지형 98%, 오른쪽 이미지형 96%(모바일 94%)로 유지하고, 페이드 구간에만 투명도를 집중한다. 오른쪽 이미지형은 마스크 영역 전체를 채우고, 왼쪽 끝에서 완전히 투명해진다. 여러 투명도 지점을 두어 전환 양끝을 완만하게 연결한다. 이미지별 `thumbnail.focalPoint`로 크롭 기준점을 조정하며 사진 영역 자체를 밀거나 줄이지 않는다.

## 상태와 기능 범위

검색어·주제·활동·대표 도구 선택은 URL의 `q`, `topic`, `activity`, `feature`에 저장한다. 입력마다 방문 기록을 늘리지 않는다. 한국어 조합 입력이 끝난 뒤 검색한다. 목록 DOM을 교체하지 않아 입력 초점을 유지한다.

자바스크립트가 없어도 전체 도구와 소개·실행 링크를 사용할 수 있다. 도구 앱은 기존 주소에서 새 탭으로 열리므로 기존 브라우저 저장 영역을 변경하지 않는다.

인증, 수업 관리, 서버 저장, N100 서버 연결, Cloudflare 배포 설정은 아직 추가하지 않았다. 필요가 생기면 각 기능의 책임과 데이터 흐름을 정한 뒤 확장한다.
