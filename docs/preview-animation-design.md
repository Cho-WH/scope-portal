# 대표 도구 미리보기 애니메이션 설계

작성일: 2026-10-15. 상태: 구현 전 설계안. 기준 포털 커밋: `226ead6`.

## 1 설계 결론

**계산은 제작 단계에서 끝내고 저장한다. 포털에서는 저장된 도형과 값을 읽어 화면만 움직인다.** 동영상, GIF, 앱 iframe, 포털 안의 실시간 물리 엔진은 사용하지 않는다. 세 장면 모두 코드로 재생하지만, 원본 앱의 계산 결과와 표현 규칙을 근거로 삼는다.

| 도구 | 미리 저장할 결과 | 방문자의 화면에서 움직일 것 |
| --- | --- | --- |
| 회로봄 | 직병렬 회로의 전위·전류, 색·높이, 투영된 회로 좌표와 전류 경로 | 평면 회로에서 입체 전위 표현으로 전환, 전류 방향 표시 |
| 파동의 간섭 | 정상 상태 한 시각의 파동장, 두 경로의 파형, P의 경로차·위상 관계 | 고정된 두 경로를 회전·이동해 펼치기, 경로차 표시 |
| 기체의 온도와 압력 | 명시적인 예시 측정점과 원본 함수로 계산한 추세선 | 장비 그림 옆 산점도 출현, 추세선 그리기 |

파동 전파, 파원 진동, P의 진동은 재생하지 않는다. 파동의 물리 시간은 처음부터 끝까지 고정한다. 기체 역시 실시간 측정 장면을 위조하지 않고, ‘예시 데이터’로 자료 분석 흐름을 소개한다.

이번 작업은 설계 문서 작성까지다. 포털의 기존 정적 미리보기와 원본 앱 코드는 변경하지 않는다. 아래 경로·타입·수치 중 별도 표시한 것은 구현 시 사용할 제안이며, 이미 존재하는 기능과 구분한다.

### 제작 단계와 재생 단계

```text
원본 앱의 고정된 소스 + 장면 입력
                  ↓ 제작 도구
물리 계산 · 정상 상태 샘플링 · 회귀 · 카메라 투영
                  ↓ 검증
장면 데이터 + 정적 대체 이미지 + 출처 명세
                  ↓ 포털
SVG / 고정 Canvas + 공통 재생 제어기
```

제작 도구에서 React·Three.js·원본 엔진을 사용하는 것은 가능하다. 이 의존성을 포털 배포 번들에 넣지 않는다. 포털에서 허용하는 계산은 시간에 따른 보간, 이동·회전, 투명도, 저장된 경로 위 표시 위치와 반응형 배치 등 **표현을 위한 계산**이다. 전기회로 풀이, 파동 샘플링, 위상차 계산, 회귀 계산은 제작 단계에서만 수행한다.

매 프레임의 화면을 이미지로 저장해 재생하는 방식도 사용하지 않는다. 저장 대상은 재사용 가능한 좌표·색·값·소수의 자세 데이터다.

### 고정할 장면

`FIX-04`의 회로와 `layoutExample()` 배치를 사용한다. 이상적 DC 해석을 기준으로 다음 값을 제작 시 확인하고 저장한다.

| 물리량 | 값 |
| --- | --- |
| 전원 | 12 V |
| 직렬 저항 R1 | 2 Ω |
| 병렬 저항 R2 / R3 | 3 Ω / 6 Ω |
| 전체 / R2 / R3 전류 | 3 A / 2 A / 1 A |
| 높은 노드 / 분기 노드 / 기준 노드 전위 | 12 V / 6 V / 0 V |
| 각 저항의 전압 강하 | 6 V |

fixture의 기대값을 화면에 단순히 복사하는 것으로 검증을 대신하지 않는다. 제작 시 원본 해석기로 다시 계산하고 기대값과 비교한다. 부품 모델이나 내부저항을 켠 결과에 위 이상적 해석값을 섞지 않는다.

시선은 ‘같은 회로가 전위 높이를 갖는다’에 집중시킨다. 처음부터 완성된 회로를 보여주며, 부품 배치·메뉴 클릭·마우스 이동은 생략한다. 색은 원본 전위 팔레트를 유지하고 포털 강조색으로 물리적 색 의미를 바꾸지 않는다.

### 장면 순서 제안 — 6.5초

| 시간 | 표현 |
| --- | --- |
| 0–1.2초 | 직병렬 회로의 평면 기호와 연결을 보여준다. 전위색은 약하게 시작한다. |

전류 표시는 전하 입자 추적이 아닌 원본의 방향 표현이다. 분기점에서 표시 개수를 입자처럼 보존하거나, 전류 3 A가 1 A보다 세 배 빨리 이동한다고 연출하지 않는다.

### 미리 저장할 데이터와 렌더러

1. 노드별 전위, 소자·도선 전류, 부호·방향, 색·띠 너비·간격을 저장한다.
2. 원본 배선과 소자 기호를 안정적인 ID가 있는 선·경로·면으로 추출한다.
3. 원본의 카메라와 높이 전환을 제작 시 계산하여 약 36개의 자세를 저장한다. 각 자세는 같은 ID의 도형 좌표·라벨 위치·앞뒤 그리기 순서를 갖는다. 필요한 샘플 수는 전환 중 오차를 보고 조절한다.
4. 포털의 SVG 렌더러는 인접 자세 사이의 좌표만 보간한다. 원본의 easing을 이미 반영한 자세에 easing을 중복 적용하지 않는다.
5. 전류 흐름은 최종 투영 경로와 누적 길이를 읽어 표시한다. 이 장면에서는 카메라 이동 중 흐름을 잠시 숨겨, 움직이는 투영 경로와 흐름의 동기화 복잡도를 줄인다.

가장 큰 제작 과제는 원본 WebGL 장면을 SVG 도형으로 옮길 때 소자 기호와 가림 관계를 유지하는 것이다. 원본은 카메라 진입 로직이 컴포넌트 내부에 있어 즉시 호출 가능한 추출 API가 아니다. 제작 전용 어댑터를 만들고, 0 / 25 / 50 / 75 / 100% 자세를 원본과 비교한다. 3D 튜브의 조명까지 복제하는 대신 연결·높이·전위색·전류 표현을 정확히 보존한다. 이를 실제 앱 전체 화면 녹화라고 표현하지 않는다.

## 4 파동의 간섭

- [geometry/layout.ts](https://github.com/Cho-WH/interference/blob/58cc7833eb2374f07db89e614a461316bd58c434/src/geometry/layout.ts)의 `interpolatePathPlacement()`는 경로를 회전·이동하며 거리 축척을 유지한다.
- [runtime/comparison-transition.ts](https://github.com/Cho-WH/interference/blob/58cc7833eb2374f07db89e614a461316bd58c434/src/runtime/comparison-transition.ts)는 일반 모드에서 1,400ms 동안 펼친 뒤 320ms 동안 안내 표시를 드러낸다. 교사 모드에는 별도 전환이 있으므로 두 타임라인을 혼합하지 않는다.
- [views/comparison.ts](https://github.com/Cho-WH/interference/blob/58cc7833eb2374f07db89e614a461316bd58c434/src/views/comparison.ts)는 같은 거리 지점, 추가 경로, 파장 눈금과 경로차를 표시한다.

### 고정할 정상 상태

동위상·등진폭의 두 파원을 정지시킨 정상 상태에서 `Δr = λ/2`인 P를 사용한다. 순간적으로 변위가 0인 점을 마디라고 판단하지 않는다. 정상 상태에서 합성 진폭이 0인 조건을 원본 엔진으로 검증한다.

| 항목 | 제작 입력 제안 |
| --- | --- |
| 파원 1 / 파원 2 | `(0.4, 0.21)` / `(0.4, 0.51)` m |
| 파장 | 0.15 m = 15 cm |
| P | `(0.85, 0.23790884552925223)` m |
| r1 / r2 | 약 0.4508646179 / 0.5258646179 m |
| 경로차 | 0.075 m = 7.5 cm = λ/2 |

위 P는 기본 파원 좌표에 대해 거리차 방정식을 풀어 얻은 제안 좌표다. 반올림한 표시값으로 좌표를 다시 만들지 않는다. 제작 시 엔진이 반환하는 경로차·정상 상태·합성 진폭과 대조한다.

두 성분의 반대 방향 변위가 잘 보이는 시각 `t0`를 한 번 선택한다. 파동장·경로 곡선·P의 성분값을 **모두 같은 t0**에서 저장한다. 이후 물리 시간을 진행시키지 않는다. 배경의 물결도, 경로 위 파형도 흐르지 않는다.

### 장면 순서 제안 — 5.5초

| 시간 | 표현 |
| --- | --- |
| 0–1.2초 | 정지된 파동 무늬, 두 파원과 마디선 위 P, P로 이어지는 두 경로를 보여준다. P를 가리키는 짧은 강조만 허용한다. |
| 1.2–2.6초 | 두 경로를 같은 축척의 평행한 두 줄로 펼친다. 고정된 파형 전체가 선분과 함께 회전·이동한다. 배경은 서서히 물러난다. |
| 2.6–2.92초 | 두 시작점 정렬, 같은 거리 보조선과 남는 구간 표시를 드러낸다. |
| 2.92–4.0초 | `경로차 7.5 cm = λ/2`를 표시하고, 두 끝점이 같은 P에서 반대 위상을 갖는다는 관계를 보여준다. |
| 4.0–5.5초 | 마지막 비교 장면을 읽을 수 있도록 유지하고 정지한다. |

### 미리 저장할 데이터와 렌더러

- 정상 상태 여부, 입력값, `t0`, P의 거리·성분 변위·합성 진폭·위상 관계.
- 경로별 거리/변위 샘플과 원본의 파원 색·선 스타일. 짧은 경로 끝에 해당하는 거리를 긴 경로 샘플에도 포함한다.
- 공간 배치와 펼친 배치의 원점·각도·공통 축척, 경로차 괄호와 라벨 좌표.
- 고정된 배경 파동장의 색 인덱스 격자와 팔레트. 초기 목표는 약 384×160 셀이며 최종 장면의 좌표계와 가독성에 맞춰 확정한다.

배경은 저장된 색 인덱스를 Canvas에 최초 한 번 그린다. resize 시 필요한 재출력은 허용하지만 애니메이션 루프에서 파동장을 다시 계산하거나 그리지 않는다. 고정된 Canvas의 투명도만 바꾸고, 경로와 표시는 SVG로 움직인다. 수만 개의 SVG 셀을 만들지 않는다.

경로는 안정된 샘플 배열 하나를 공유한다. 각 파형을 별도로 늘여 길이를 맞추지 않는다. 배경, P, 경로의 화면 배율은 같아야 한다. 마지막 두 행의 P가 서로 다른 관측점처럼 보이지 않도록 끝점 표기 또는 ‘같은 P’ 연결 표시를 유지한다.

현재 배너 사진의 기본 P는 두 경로 길이가 같은 위치여서 이번 마디선 장면의 근거로 재사용하지 않는다. 새 계산 결과에서 정적 대체 이미지도 함께 만든다.

## 5 기체의 온도와 압력

### 원본에서 확인한 것

- [assets/setup.svg](https://github.com/Cho-WH/bme280/blob/8c8e2c5466635c935206a1e520a42cedc449216c/gay-lussac/assets/setup.svg)는 센서·마이크로비트·배터리를 모두 밀폐 용기 안에 배치한다. 물은 용기 바깥 수조에 있고, 배선은 밀폐 경계를 넘지 않으며 Bluetooth로 값을 전송한다.
- [analysis/graph-data.js](https://github.com/Cho-WH/bme280/blob/8c8e2c5466635c935206a1e520a42cedc449216c/gay-lussac/analysis/graph-data.js)는 유효한 분석 대상 점과 제외점을 구분한다.
- [analysis/regression.js](https://github.com/Cho-WH/bme280/blob/8c8e2c5466635c935206a1e520a42cedc449216c/gay-lussac/analysis/regression.js)의 `linearFit()`·`predict()`·`trendGeometry()`가 회귀와 추세선 좌표를 제공한다.
- [ui/chart-view.js](https://github.com/Cho-WH/bme280/blob/8c8e2c5466635c935206a1e520a42cedc449216c/gay-lussac/ui/chart-view.js)의 분석 차트는 `animation: false`다. 이번 점 출현·선 그리기는 포털용으로 새로 설계하는 연출이다.

기존 포털의 `public/images/previews/gas.svg`는 보드를 용기 밖에 그리고 있어 원본 실험 배치와 다르다. 새 구현에서는 이를 바탕으로 확장하지 않고 원본 장비 SVG의 구조를 따라 정리한다. 이 문서 작성 단계에서는 기존 파일을 바꾸지 않는다.

### 장면 구성

그림 영역 안에서 장비는 왼쪽 약 35%, 그래프는 오른쪽 약 65%를 사용한다. 장비를 다시 작게 그리는 것보다 용기·센서·수조·무선 전송 관계만 남긴다. 그래프는 X축 `온도 (°C)`, Y축 `압력 (hPa)`를 고정한다.

작은 온도·압력 숫자를 계속 갱신하거나 장치 연결 상태를 연출하지 않는다. 장비와 분석을 연결하는 짧은 점선 또는 표시 한 번으로 흐름을 설명한다. 수조 색의 미세한 변화는 가능하지만 입자 운동·열 전달 시뮬레이션은 추가하지 않는다.

### 예시 데이터와 추세선

제작용 고정 자료로 20–50 °C 구간의 12개 점을 사용한다. 예를 들어 `P(T) = 1000 × (T + 273.15) / 293.15 + ε` hPa를 기준으로 작고 고정된 오차를 더한다. 기준 압력·온도와 오차 목록은 제작 명세에 명시한다. 무작위 값은 방문 시 생성하지 않는다.

이 식은 일정한 부피·기체량의 예시 관계를 만드는 입력이다. 실제 측정 결과나 센서 정확도 보증이 아니다. **그래프 가까이에 ‘예시 데이터’를 계속 표시**하고, 접근성 설명에도 같은 내용을 넣는다. 원본 `linearFit()`로 전체 고정 점을 계산해 추세선의 양 끝과 계수를 저장한다.

포털은 점을 순서대로 보여주고 저장된 추세선을 그리기만 한다. 추세선을 보기 좋게 임의로 맞추거나 매번 새로 피팅하지 않는다. 섭씨 그래프를 원점에 강제로 통과시키지 않는다. 첫 버전에는 절대영도 외삽, R², 회귀식 전체, 센서 오차 설명을 넣지 않는다.

### 장면 순서 제안 — 6.5초

| 시간 | 표현 |
| --- | --- |
| 0–0.8초 | 장비와 그래프 축이 드러난다. ‘예시 데이터’는 처음부터 표시한다. |
| 0.8–1.5초 | 장비에서 그래프로 이어지는 짧은 표시가 나타난다. |
| 1.5–3.9초 | 저장된 12개 점을 약 0.2초 간격으로 나타낸다. 튀는 확대나 탄성 효과는 쓰지 않는다. |
| 3.9–4.8초 | 마지막 점이 나온 뒤 측정 범위 안에서 추세선을 왼쪽부터 그린다. |
| 4.8–6.5초 | 산점도와 추세선을 함께 보여준 뒤 정지한다. |

### 렌더러

전체를 SVG로 구현한다. 장비의 선·면, 축, 12개 원, 추세선으로 충분하므로 Chart.js나 별도 그래프 라이브러리를 추가하지 않는다. 점의 출현은 opacity로, 추세선은 저장된 끝점과 `pathLength`·dash offset으로 표현한다. 바탕은 투명하고 선 두께·문자색은 포털 토큰에 맞춘다. 복수 인스턴스를 고려해 SVG의 clipPath·marker ID를 인스턴스별로 구분한다.

## 6 공통 화면과 재생 규칙

### 배치

현재 승인된 문구·버튼·도구 선택자 위치를 유지한다. 그림 영역은 선택자를 포함한 배너 전체 높이에 맞춘다. 공통 제작 좌표계는 `viewBox="0 0 1200 480"`을 출발점으로 삼고, 도형 비율을 보존한다.

왼쪽 페이드 안에 핵심 정보가 들어가지 않도록 내용 배치와 마스크를 함께 정한다. 현재 정적 배너의 마스크는 가로 54%에서 완전히 선명해져 복잡한 설명 장면을 많이 가릴 수 있다. 새 장면은 왼쪽 약 24%를 여백으로 예약하고, 32–36% 이후의 주요 내용이 충분히 보이도록 조정하는 안을 검토한다. 이는 기존 정적 이미지 마스크를 모든 장면에 복사하지 않는다는 뜻이다.

전위 숫자, P, 반 파장 구간, 그래프 축 이름은 페이드 밖에 둔다. 위아래 페이드는 배경에 적용하고 핵심 문자까지 흐리지 않는다. 1200px 제작 좌표에서 28px인 글자는 600px 표시에서 14px가 된다는 점을 기준으로 최종 크기를 확인한다.

### 재생 정책 제안

- 데스크톱에서 선택된 장면 하나만 준비하고, 배너가 충분히 보일 때 한 번 자동 재생한다. 자동 탭 전환과 무한 반복은 하지 않는다.
- 장면 종료 후 마지막 상태를 유지한다. 작고 명확한 `다시 보기` 버튼으로 재생할 수 있다. 재생 중에는 `일시 정지`, 정지 중에는 `계속 보기`를 제공한다.
- 사용자가 명시적으로 멈췄다면 스크롤 복귀·탭 복귀로 자동 재생하지 않는다.
- 다른 도구를 선택하면 기존 장면의 실행을 멈춘다. 이 방문에서 이미 완료한 장면은 최종 상태로 돌아오고, 다시 보기로 시작한다.
- 문서가 숨겨지거나 배너가 화면 밖으로 나가면 정지한다. 복귀 시 경과 시간을 한꺼번에 따라잡지 않는다.
- `prefers-reduced-motion: reduce`에서는 설명이 완성된 정적 상태를 기본으로 표시한다. 명시적인 다시 보기 요청이 있을 때만 재생한다.
- 모바일 680px 미만에서는 현재처럼 미리보기 DOM·장면 데이터·포스터·렌더러를 요청하지 않는다. 680–959px에서는 가독성을 먼저 확인하고, 필요하면 정적 요약으로 대체한다. 자동으로 확대·잘라내어 핵심 표기를 없애지 않는다.
- JavaScript 비활성화 또는 로딩 실패 때도 기존 문구와 실행 링크는 사용할 수 있다. 오류가 나면 정적 포스터로 대체하고 원본 앱 실행을 막지 않는다.

재생 버튼은 그림의 마스크 바깥 독립 레이어에 둔다. 현재 `.feature-preview`의 `pointer-events: none`을 그대로 적용하면 버튼을 누를 수 없으므로, 시각 레이어만 비활성으로 두고 버튼은 별도로 처리한다. 버튼은 키보드 초점과 최소 44px 터치 영역을 갖는다. SVG 도형에는 개별 탭 정지를 만들지 않고 장면 전체에 제목·요약을 제공한다. 무음 장면이므로 오디오를 추가하지 않는다.

## 7 모듈과 데이터 계약 제안

### 파일 구성

```text
tools/preview-bake/              제작 전용 패키지와 잠금 파일
  sources.lock.json              원본 URL·커밋·참조 경로
  scenes/{circuit,waves,gas}/     입력·추출기·검증 규칙
  build.mjs                      도구 하나씩 데이터 생성
src/features/preview/
  Preview.astro                  종류에 따른 정적 호스트
  controller.ts                  활성·가시성·재생 수명 관리
  clock.ts                       표현 시간만 관리
  registry.ts                    허용된 장면별 지연 로딩
  scenes/circuit.ts              SVG 자세·전류 표시
  scenes/waves.ts                정적 Canvas + SVG 펼치기
  scenes/gas.ts                  SVG 장비·점·추세선
public/previews/{scene}/{rev}/   검증된 데이터·대체 포스터
docs/preview-animation-design.md
```

제작 도구는 일반 `npm run build`와 분리한다. 원본 코드가 바뀌었다고 포털 빌드 때 임의로 최신 값을 가져오지 않는다. 산출물은 제작 명령으로 명시적으로 갱신하고 diff·장면 검토 후 채택한다. 복제한 원본 저장소 전체나 수많은 캡처를 포털 Git에 넣지 않는다.

### 콘텐츠의 선택 필드

기존 `preview.kind: "placeholder"`를 유지하면서 `kind: "baked-scene"`을 추가하는 판별 가능한 스키마를 제안한다.

```json
{
  "kind": "baked-scene",
  "scene": "waves",
  "revision": "1",
  "manifest": "/previews/waves/1/manifest.json",
  "poster": {
    "src": "/images/previews/waves-final.webp",
    "alt": "같은 P까지 펼친 두 경로의 길이가 반 파장만큼 다름을 보여주는 장면",
    "width": 1200,
    "height": 480
  }
}
```

manifest에는 형식 버전, 원본 커밋, 입력 해시, 생성기 버전, 물리 가정, 좌표계, 길이·단위, durationMs, 단계별 시간, 데이터 경로·해시·크기, 정적 최종 상태를 넣는다. 실제 값·곡선은 장면 데이터가 소유하고, 콘텐츠 JSON은 제목·실행 주소와 장면 선택만 소유한다. 최종 상태와 대체 포스터는 같은 저장 결과에서 생성한다.

`src/lib/catalog/schema.ts`에서 장면 ID와 manifest 경로를 검증하고, `scripts/validate-content.ts`는 manifest·데이터·포스터 존재 여부, 지원하는 형식 버전, 해시와 좌표/시간 값의 유효성까지 검사하도록 확장한다. 기존 포스터 파일 검사만 통과했다고 새 장면이 유효하다고 판단하지 않는다.

회로 자세와 파동 샘플의 배열 형식은 각 장면이 소유한다. 모든 장면을 하나의 거대한 범용 애니메이션 JSON 문법으로 만들지 않는다. 공통화하는 것은 수명 관리·시간·상태·접근성·파일 검증이다.

```ts
interface PreviewScene {
  durationMs: number;
  renderAt(timeMs: number): void;
  resize(width: number, height: number): void;
  dispose(): void;
}
```

`renderAt(t)`는 같은 저장 데이터와 t에 대해 같은 화면을 만든다. RAF 루프는 공통 제어기 하나만 소유한다. 물리 시간과 재생 시간은 별개이며 파동의 `t0`는 불변이다. 재생 중 resize해도 데이터나 진행 상태를 다시 생성하지 않는다.

제어기는 `idle → loading → ready → playing / paused → ended`와 실패 시 `fallback`을 관리한다. 빠르게 탭을 바꿀 때는 AbortController와 요청 세대 번호로 오래된 응답의 장면 장착을 막는다. 비활성화 시 RAF·이벤트·관찰자를 정리하고, 완료된 장면의 순수 데이터는 세션 안에서 재사용할 수 있다.

현재 `featured.ts`의 `syncPreview()`는 선택된 데스크톱 패널에만 템플릿을 삽입한다. 이 경계를 유지하되 단순 `figure.remove()` 대신 장면의 정리 함수를 먼저 호출한다. URL의 `feature`, 키보드 탭 이동과 밑줄 동작은 유지한다. 장면이 없는 새 도구는 정적 미리보기 또는 기존 대체 표현을 계속 사용할 수 있다.

## 8 제작 검증과 성능 목표

목표치는 아직 측정값이 아니다. 첫 장면 구현 후 실제 전송 크기와 프레임 비용을 보고 조정한다.

| 항목 | 초기 목표 |
| --- | --- |
| 추가 재생 코드 | 공통 코드와 선택된 렌더러를 합쳐 gzip 40 KiB 이내 |
| 장면 데이터 | 선택된 장면당 gzip 250 KiB 이내, 초과 시 좌표 정밀도·샘플 수부터 검토 |
| 정적 대체 포스터 | 장면당 100 KiB 이내 목표 |
| 활성 장면 | 최대 1개, 비활성 상태의 연속 프레임 작업 0 |
| 화면 갱신 | 60Hz 화면의 프레임 예산 안에서 작동, 매 프레임 DOM 크기 측정 없음 |
| 모바일 최초 진입 | 미리보기 자산과 코드 요청 0 |

테스트는 단순 구현 복제 대신 다음 계약을 검증한다.

- **회로:** 12 / 6 / 0 V와 3 / 2 / 1 A, 전류 분배, 병렬 양단 전위 일치, 원본 팔레트, 전환 중 연결 보존. 원본의 3D 자세와 주요 단계 비교.
- **파동:** 정상 상태·반 파장 경로차·합성 진폭 0, 경로 끝과 P의 성분값 일치, 전환 전후 축척·길이·샘플 동일, 재생 중 물리 시간 불변. 고정 배경 픽셀은 opacity 변경 외에는 바뀌지 않음.
- **기체:** 모든 점이 고정 예시 데이터와 일치, 저장 추세선이 원본 `linearFit()` 결과와 일치, 축·단위·예시 표기, 장비와 밀폐 경계의 일치.
- **재현성:** 같은 입력·원본 커밋·생성기에서 같은 데이터를 얻는다. manifest의 생성 시각은 콘텐츠 해시 계산에서 제외한다.
- **재생 수명:** 빠른 탭 전환, 화면 밖 정지, 사용자 정지 유지, 동작 감소, 다시 보기, resize, 데이터 실패, 모바일 요청 부재.
- **시각 검토:** 1280 / 1024 / 768 / 360px 화면, 원래 문구·버튼·선택자 위치, 페이드와 핵심 수치의 겹침, 한 번 재생 후 의미가 읽히는지 확인.

## 9 구현 순서와 완료 기준

1. **회로봄:** 고정 예제 계산 → 시작·종료 SVG 비교 → 원본 진입 자세 추출 → 공통 재생기로 한 번 재생. 가장 어려운 원본 3D 표현 추출을 먼저 검증한다.
2. **파동:** 정확한 마디선 P 검증 → 한 시각의 배경·경로 저장 → 축척을 유지하는 펼치기 → 경로차 표시. 파동 전파 코드는 포털로 가져오지 않는다.
3. **기체:** 원본 장비 배치로 SVG 정리 → 예시 점·회귀 결과 저장 → 점 출현·추세선 순서 구현.
4. **통합:** 콘텐츠 스키마·파일 검증·지연 로딩·정적 대체·모바일·정지/재생 동작을 정리한다.

각 장면은 계산 근거, 읽을 수 있는 시작·종료 상태, 재생 정지 동작이 갖춰졌을 때 완료로 본다. 먼저 한 장면의 실제 크기 시안을 확인한 뒤 나머지를 확장한다. 원본 코드를 참고했다고 원본 앱의 모든 기능을 포털에서 지원한다고 표현하지 않는다.

다음 작업의 구체적인 시작점은 **회로봄 혼합 회로의 계산 결과와 두 자세를 추출해 정적 SVG로 비교하는 것**이다. 그 비교를 통과하면 움직임을 붙인다. 이번 문서에서는 애니메이션·데이터 파일을 아직 생성하지 않았다.
